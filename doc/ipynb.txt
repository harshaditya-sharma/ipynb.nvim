INTRODUCTION                                               *ipynb-introduction*

ipynb.nvim is a modal Jupyter notebook editor for Neovim.
Requires Neovim 0.10+.

Features:
- Reads and writes .ipynb exactly like Jupyter (saving an untouched notebook
  changes nothing; attachments, tags and app metadata are kept)
- Cell-based editing in an overlay on the cell or in a split beside the
  notebook (|ipynb-split-editor|)
- Partial language server support (completion, diagnostics, go-to-definition,
  references, rename, formatting); IPython magics are hidden from servers
- Any Jupyter kernel: local, on a Jupyter server (|:NotebookServerConnect|),
  or a connection file; iron.nvim REPL fallback when there is no kernel
- Run all / above / below / selection, restart and run all, run times,
  queued state, clear_output and display updates, input() prompts
- Coloured tracebacks, readable HTML/Markdown fallbacks, truncated long
  outputs, images inline (kitty, Sixel, iTerm2) or in your viewer
- Tags, titles, hide code / hide outputs shared with JupyterLab, Colab and
  Databricks (|ipynb-compatibility|)
- Variable inspector, cell picker, folding, export (|:NotebookExport|)

Open any .ipynb file and use `i` to enter Cell mode, `]]`/`[[` to navigate.

SETUP                                                             *ipynb-setup*

                                                                 *ipynb.setup()*
require('ipynb').setup({opts})

    Call this in your Neovim configuration to enable ipynb.nvim.
    The plugin will handle .ipynb files automatically.

    Example with lazy.nvim: >lua
        {
            "ajbucci/ipynb.nvim",
            dependencies = {
                "nvim-treesitter/nvim-treesitter",
                "neovim/nvim-lspconfig",
            },
            opts = {},
        }
<
    The treesitter parser is automatically compiled on first load.
    Example with defaults: >lua
        require('ipynb').setup({
            float = {
                layout = 'overlay', -- or 'split'
            },
            keymaps = {
                next_cell = ']]',
                prev_cell = '[[',
                execute_cell = '<C-CR>',
                execute_and_next = '<S-CR>',
            },
            kernel = {
                auto_connect = false,
                python_path = nil,
            },
            images = {
                enabled = true,
                max_height = 30,
            },
        })
<
    Parameters: ~
        {opts}  (NotebookConfig|nil)  See |ipynb-config|

MARKDOWN RENDERING                              *ipynb-markdown-rendering*

Markdown cells are exposed as injected Markdown trees while the notebook
facade keeps its `ipynb` filetype. Renderers that support Tree-sitter
injections can display headings, links, lists, and LaTeX persistently in
Notebook mode.

render-markdown.nvim ~

    Add `ipynb` to its filetype list: >lua
        require('render-markdown').setup({
            file_types = { 'markdown', 'ipynb' },
            overrides = {
                filetype = {
                    ipynb = {
                        -- Optional: keep the cursor line rendered.
                        anti_conceal = { enabled = false },
                    },
                },
            },
        })
<
    The `file_types` entry is required. The `anti_conceal` override is optional
    and keeps the cursor line rendered. If the plugin specification uses an
    `ft` key, include both `markdown` and `ipynb` there as well. LaTeX rendering
    requires the optional LaTeX parser and renderer dependencies documented by
    render-markdown.nvim.

markview.nvim ~

    Add `ipynb` to `preview.filetypes` while retaining its defaults: >lua
        require('markview').setup({
            preview = {
                filetypes = {
                    'markdown', 'quarto', 'rmd', 'typst', 'asciidoc', 'ipynb',
                },
            },
        })
<
    Do not change the notebook buffer's filetype to `markdown` or
    `ipynb.markdown`. The `ipynb` filetype selects the parser that identifies
    cell boundaries and provides the Markdown injections.

FloatConfig                                                        *FloatConfig*

    Fields: ~
        {layout}             (string)   'overlay': edit on top of the cell
                                        'split': edit in a split beside the
                                        notebook |ipynb-split-editor|
                                        Default: 'overlay'
        {split}              (table)    { position = 'right'|'left'|'below'
                                        |'above', size = fraction of the
                                        notebook window }
                                        Default: { position = 'right',
                                        size = 0.45 }
        {show_line_numbers}  (boolean)  Line numbers in the overlay
                                        Default: false

                                                          *ipynb-split-editor*
    With `layout = 'split'` the cell editor is a normal window next to the
    notebook. The notebook side stays scrollable (and read-only while it has
    focus), so earlier cells and outputs remain visible while typing.
    Pressing `i` on another cell, or <C-j>/<C-k> in the editor, reuses the
    same split. <Esc>, |:quit| or <C-w>c end the edit session.

KEYMAPS                                                         *ipynb-keymaps*

Keymaps are organized by where they apply:
- [N] = Notebook mode only
- [C] = Cell mode only
- [N+C] = Both Notebook mode and Cell mode

Notebook mode only (entering Cell mode, cell operations): ~

    These work only in Notebook mode.

    `<CR>`       [N]   Enter cell in Normal mode
    `i`          [N]   Enter cell in Insert mode (insert)
    `a`          [N]   Enter cell in Insert mode (append)
    `I`          [N]   Enter cell in Insert mode (insert at line start)
    `A`          [N]   Enter cell in Insert mode (append at line end)
    `o`          [N]   Enter cell in Insert mode (open line below)
    `O`          [N]   Enter cell in Insert mode (open line above)
    `dd`         [N]   Cut cell
    `p`          [N]   Paste cell below
    `P`          [N]   Paste cell above
    `]]`         [N]   Jump to next cell
    `[[`         [N]   Jump to previous cell
    `<M-j>`      [N]   Move cell down
    `<M-k>`      [N]   Move cell up
    `<M-CR>`     [N]   Execute cell, insert below
    `<C-c>`      [N]   Interrupt kernel

Cell mode only: ~

    `<Esc>`      [C]   Exit cell, return to Notebook mode
    `<C-j>`      [C]   Enter next cell
    `<C-k>`      [C]   Enter previous cell

Both Notebook mode and Cell mode: ~

    These work in both contexts.

    `<S-CR>`     [N+C] Execute cell, move next
    `<C-CR>`     [N+C] Execute cell, stay
    `u`          [N+C] Undo (global)
    `<C-r>`      [N+C] Redo (global)

<leader>k menu (works in both Notebook mode and Cell mode): ~

    `<leader>ka` [N+C] Add cell above
    `<leader>kb` [N+C] Add cell below
    `<leader>km` [N+C] Make markdown
    `<leader>ky` [N+C] Make code
    `<leader>kr` [N+C] Make raw
    `<leader>ko` [N+C] Open output in float
    `<leader>kc` [N+C] Clear cell output
    `<leader>kC` [N+C] Clear all outputs
    `<leader>kx` [N+C] Execute cell
    `<leader>kX` [N+C] Execute cell, move next
    `<leader>ki` [N+C] Interrupt kernel
    `<leader>k0` [N+C] Restart kernel
    `<leader>ks` [N+C] Start kernel
    `<leader>kS` [N+C] Shutdown kernel
    `<leader>kn` [N+C] Kernel info
    `<leader>kj` [N+C] Jump to cell (picker)
    `<leader>kf` [N]   Toggle cell fold (Notebook mode only)

Inspector (works in both Notebook mode and Cell mode): ~

    `<leader>kh` [N+C] Inspect variable
    `<leader>kv` [N+C] Inspect cell
    `<leader>kH` [N+C] Toggle inspect auto-hover

LSP: ~

    Partial language server support via shadow buffer. Most LSP keymaps
    (`gd`, `gr`, `K`, rename, etc.) should work, but not all - compatibility
    depends on your LSP plugins and configuration.

    Supported LSP features:
    - Diagnostics (errors, warnings inline)
    - Completion (triggered with `<C-Space>` in Cell mode)
    - Hover (`K`)
    - Go to definition (`gd`)
    - Go to references (`gr`)
    - Rename (`vim.lsp.buf.rename()`)
    - Formatting (`vim.lsp.buf.format()`)

    Not supported: code actions (can span cell boundaries unsafely).

COMMANDS                                                       *ipynb-commands*

All commands are prefixed with `:Notebook` and operate on the current buffer.

Cell Operations: ~

    `:NotebookInsertCellBelow`     Insert a new cell below current
    `:NotebookInsertCellAbove`     Insert a new cell above current
    `:NotebookDeleteCell`          Delete the current cell
    `:NotebookCutCell`             Cut cell to register
    `:NotebookPasteCellBelow`      Paste cell below
    `:NotebookPasteCellAbove`      Paste cell above
    `:NotebookMoveCellUp`          Move current cell up
    `:NotebookMoveCellDown`        Move current cell down
    `:NotebookToggleCellType`      Toggle between code and markdown
    `:NotebookMakeCode`            Convert cell to code
    `:NotebookMakeMarkdown`        Convert cell to markdown
    `:NotebookMakeRaw`             Convert cell to raw

Execution: ~

    `:NotebookExecuteCell`         Execute current cell, stay
    `:NotebookExecuteAndNext`      Execute current cell, move to next
    `:NotebookExecuteAllBelow`     Execute all cells from current to end
    `:NotebookExecuteAllAbove`     Execute all cells above the current one
    `:NotebookExecuteAll`          Execute all code cells
    `:NotebookRestartAndRunAll`    Restart the kernel, then run all cells
    `:NotebookReplSend`            Send cell to the iron.nvim REPL

Kernel: ~

    `:NotebookKernelStart` [path]  Start kernel
                                   Optional: path to Python interpreter
    `:NotebookKernelConnect` {file}
                                   Connect to existing kernel via connection file
    `:NotebookKernelInterrupt`     Interrupt current execution
    `:NotebookKernelRestart`       Restart kernel (clears outputs)
    `:NotebookKernelShutdown`      Shutdown kernel
    `:NotebookKernelStatus`        Show kernel connection status
    `:NotebookSetKernel` {name}    Set kernel name in metadata
                                   Example: julia-1.10, ir, python3
    `:NotebookListKernels`         List available Jupyter kernels
                                                      *:NotebookServerConnect*
    `:NotebookServerConnect` {url} [kernel]
                                   Use a kernel on a Jupyter server
                                   (JupyterLab, JupyterHub, jupyter server).
                                   [kernel] is a running kernel id to attach
                                   to or a kernelspec name to start; without
                                   it you pick from a list. The token comes
                                   from the URL (?token=) or $JUPYTER_TOKEN.
                                   Disconnecting only shuts down kernels
                                   ipynb.nvim started.

Output: ~

    `:NotebookOutput`              Open cell output in floating buffer
    `:NotebookOpenOutput`          Open image/PDF/HTML/Plotly output in the
                                   system viewer or browser
    `:NotebookToggleOutputsHidden` Hide/show the cell's outputs
    `:NotebookClearOutput`         Clear current cell output
    `:NotebookClearAllOutputs`     Clear all outputs

Navigation: ~

    `:NotebookJumpToCell`          Open cell picker
                                   Uses vim.ui.select - works with dressing.nvim,
                                   telescope, fzf-lua, or any vim.ui.select backend

Formatting: ~

    `:NotebookFormatCell`          Format current cell using LSP
    `:NotebookFormatAll`           Format all code cells (processes bottom-to-top)

    Note: `vim.lsp.buf.format()` is wrapped to work with notebooks automatically.
    In Notebook mode it formats all cells; in Cell mode it formats
    the current cell. This means your existing format keybindings (e.g.,
    `<leader>f`) will work seamlessly with notebooks.

Folding: ~

    `:NotebookFoldCell`            Toggle fold for current cell
    `:NotebookFoldAll`             Fold all cells
    `:NotebookUnfoldAll`           Unfold all cells

Inspector: ~

    `:NotebookInspect`             Inspect variable at cursor
    `:NotebookInspectCell`         Show all variables in cell
    `:NotebookToggleAutoHover`     Toggle auto-hover on CursorHold

Other: ~

    `:NotebookCreate` [path] [kernel]
                                   Create a new notebook
                                   If no path given, creates untitled.ipynb
                                   (or untitled1.ipynb, etc. if file exists)
                                   Optional kernel sets the kernelspec
                                   Example: :NotebookCreate myfile julia-1.10
    `:NotebookSave`                Save notebook to disk
    `:NotebookInfo`                Show notebook and cell information
                                                             *:NotebookExport*
    `:NotebookExport` {format}     Export with nbconvert using the kernel's
                                   Python: html, pdf, webpdf, markdown,
                                   script (python), latex, rst, asciidoc,
                                   slides

More cell operations: ~

    `:NotebookCopyCell`            Copy cell to register
    `:NotebookMergeCellBelow`      Merge the cell with the one below
    `:NotebookSplitCell`           Split the cell at the cursor
    `:NotebookCellTags` [tags...]  Set tags, or edit them in a prompt
    `:NotebookToggleSourceHidden`  Hide/show the cell's code

TROUBLESHOOTING                                         *ipynb-troubleshooting*

Health check ~

    Run `:checkhealth ipynb` to verify all dependencies are properly
    configured.

Parser not found ~

    The parser should auto-compile on first load. If it fails:
    - Ensure nvim-treesitter is installed
    - Run `:TSInstall! ipynb` to manually compile

No LSP ~

    Ensure you have a language server installed for the notebook's language.
    Check `:LspInfo` while in the notebook to see attached clients.

Kernel won't start ~

    Check `:NotebookKernelStatus` for the Python path being used.
    Ensure `jupyter_client` is installed: `pip install jupyter_client`
    For non-Python kernels, ensure the kernel is installed (e.g., IJulia, IRkernel).

`input()` appears stuck ~

    The kernel is waiting for stdin input.
    Enter text in the floating prompt and press <CR>.
    Press <Esc> or <C-c> to cancel (interrupts the kernel).

Images not showing ~

    Requires snacks.nvim and a terminal which fully supports the kitty graphics protocol
    (kitty, Ghostty). For tmux, set `allow-passthrough=on`.

STATUSLINE                                                   *ipynb-statusline*

The plugin provides a statusline component showing kernel status with the
notebook's language icon (from nvim-web-devicons).

                                                     *ipynb.kernel.statusline()*
require('ipynb.kernel').statusline()

    Returns the kernel status string for use in statuslines.
    Shows language icon + status: IDLE, BUSY, or DISC.
    Returns empty string if not in a notebook buffer.

                                              *ipynb.kernel.statusline_visible()*
require('ipynb.kernel').statusline_visible()

    Returns true if the statusline component should be shown.
    Use as a condition function in lualine.

                                                *ipynb.kernel.statusline_color()*
require('ipynb.kernel').statusline_color()

    Returns a color table for lualine based on kernel state.
    Uses theme-aware colors:
    - IDLE: DiagnosticOk (green)
    - BUSY: DiagnosticWarn (yellow)
    - DISC: DiagnosticError (red)

Example with lualine: >lua
    require("lualine").setup({
        sections = {
            lualine_x = {
                {
                    require("ipynb.kernel").statusline,
                    cond = require("ipynb.kernel").statusline_visible,
                    color = require("ipynb.kernel").statusline_color,
                },
            },
        },
    })
<
Disable with `kernel.show_status = false` in setup.

==============================================================================
JUPYTER COMPATIBILITY                                    *ipynb-compatibility*

Files ~
    Notebooks are written like nbformat does (sorted keys, one-space indent,
    multi-line strings split into lists, CRLF kept), so saving an untouched
    notebook changes nothing and diffs stay small. Markdown attachments,
    unknown output types and all notebook/cell metadata (Colab, Kaggle,
    Databricks, widgets) are preserved. Cell IDs follow nbformat 4.5; IDs that
    don't match its pattern are replaced on load.

Metadata shared with other apps ~
    Tags                metadata.tags (JupyterLab); shown on the border,
                        edited with |:NotebookCellTags|
    Titles              Databricks cell titles and Colab "#@title" lines are
                        shown on the border
    Hidden code         metadata.jupyter.source_hidden (JupyterLab) and
                        Colab forms: the cell is folded
    Hidden outputs      metadata.jupyter.outputs_hidden plus the classic
                        metadata.collapsed flag
    Run timing          metadata.execution with |KernelConfig| record_timing

Running ~
    Cells queued after a failing cell are aborted, as in Jupyter. Magics and
    shell commands run in the kernel; for Python language servers they are
    replaced by placeholders in the shadow file and restored after
    formatting.

Remote compute ~
    Any Jupyter server works with |:NotebookServerConnect|. Databricks
    clusters are reached through Databricks Connect inside a local kernel.
    Google Colab runtimes can't be driven from outside Colab.

Not supported ~
    ipywidgets and other JavaScript outputs need a browser (HTML outputs can
    be opened with |:NotebookOpenOutput|).
